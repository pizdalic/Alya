# Аля 3

Telegram-персонаж на Python и TDLib, с характером Алы и механизмами памяти, вдохновлёнными Kuni. Рабочий каталог — `alya_next`. Запускать команды из корня репозитория.

## Установка и запуск

Требуются Linux, Python 3.11+ и FFmpeg. Текущее окружение уже установлено в `.venv-next`.

```bash
python -m venv .venv-next
.venv-next/bin/pip install -r alya_next/requirements.txt
.venv-next/bin/python -m alya_next init
.venv-next/bin/python -m alya_next doctor --online
.venv-next/bin/python -m alya_next login
.venv-next/bin/python -m alya_next run
```

`login` запросит номер, код Telegram и пароль 2FA, если он включён. Используется отдельная сессия TDLib в `alya_next/data/telegram`. Старая Telethon `SESSION_STRING` сюда не переносится. `login` только подключает аккаунт. `run` начинает обработку сообщений.

Секреты берутся из `.env` в корне репозитория. Пример переменных — `.env.example` в этой папке. Ключи в репозиторий добавлять не нужно. `--config /путь/config.toml` выбирает другой конфиг и каталог данных.

## Что работает в коде

- Личные и групповые сообщения, обращения по имени, упоминания и ответы на сообщения Алы.
- Объединение быстрых сообщений, последовательные ответы в каждом чате, отметки прочтения и имитация набора.
- Случайное вступление в групповой разговор с вероятностью и периодом ожидания из конфига.
- Запланированные посещения выбранных чатов, приоритет закреплённых и непрочитанных. Приглушённые чаты пропускаются.
- Поиск чатов и сообщений, просмотр соседних сообщений, отправка, редактирование собственных сообщений, пересылка и реакции.
- Прямые бан, удаление сообщений и теги участников через TDLib. Проверяются реальные права аккаунта. Создателя и саму Алю банить нельзя.
- Дневник, рабочая память и эмоции на диске. Поиск по эмбеддингам, переиндексация после редактирования заметок, периодическая консолидация с сохранением исходников.
- Фото, статические и видео-стикеры, кадр видео и расшифровка звука. Анимированные TGS-стикеры представлены эмодзи.
- Картинки через OpenAI-совместимый Images API или Stable Diffusion, голосовые через OpenAI-совместимый TTS, распознавание через STT.

Доступность медиа зависит от подключённых сервисов и возможностей выбранной текстовой модели принимать изображения. Отсутствующий сервис возвращает модели явную ошибку. Для видео сейчас используется первый кадр и до двух минут аудио.

## Настройки поведения

В `config.toml`:

- `allowed_chats = []` разрешает доступ ко всем уже доступным аккаунту чатам. Список ID ограничит доступ.
- `proactive_chats` перечисляет чаты для периодических самостоятельных посещений. По умолчанию пуст.
- `moderation_chats` разрешает самостоятельную модерацию в перечисленных группах. Без этого модерация требует подтверждённого запроса создателя в обрабатываемой пачке сообщений.
- `spontaneous_chance = 0.07` управляет вероятностью вступления в текущий групповой разговор.
- `cooldown_seconds = 300` ограничивает частоту инициативных сообщений.

Чтение истории других чатов и пересылка между чатами разрешены по запросу создателя. В обычном разговоре память ограничена текущим chat ID. Настройки конфигурации применяются после перезапуска, Markdown персонажа перечитывается при каждом ответе.

## Obsidian

Открыть `alya_next/data/vault` как хранилище Obsidian.

```text
Character/
  personality.md
  appearance.md
  relationships.md
Chats/<telegram_chat_id>/
  Working.md
  Emotions.md
  Diary/
  Summaries/
  Archive/
```

Исходные шаблоны лежат в `character/`. После `init` редактировать характер следует в `data/vault/Character/`. Приложение сохраняет ручные изменения рабочей памяти, сделанные во время ответа модели. Старое хранилище `alya_vault` автоматически не импортируется, поскольку имена в нём не дают однозначного соответствия Telegram ID.

## Восстановление и проверка

История, очередь, индекс векторов и журнал действий сохраняются в `data/state.sqlite3`. Неначатые ответы продолжаются после перезапуска. Ответы, прерванные во время обработки, остаются с `pending=2` для проверки — автоматическая повторная отправка может создать дубликаты. Ошибки доставки Telegram отдельно попадают в таблицу `audit`. Команда `/status` работает в личке создателя.

```bash
.venv-next/bin/pip install pytest pytest-asyncio
.venv-next/bin/python -m pytest alya_next/tests -q
```

Тесты используют поддельный клиент Telegram. Проверки настоящих прав модерации, доставки и авторизации выполняются на подключённом аккаунте. Созданные медиа остаются в `data/media`, чтобы TDLib успела их загрузить. Каталог со временем нужно очищать от старых отправленных файлов.

## Проверено на этой установке

Восемь автономных тестов проходят. Живой DeepSeek проверен на текстовом ответе, вызове инструмента и сохранении эмоций/дневника, с подменой отправки Telegram в последней проверке.

Настроены `deepseek-v4.1-flash` и `Nano-Banana-2` через ClaudeHub. Первоначальная модель gpt-image-2.5-sunburst на проверке Images API вернула HTTP 502 `Authentication failed`. По запросу владельца выбрана Nano-Banana-2, тестовое изображение успешно создано. Текстовая модель с тем же ключом работает. STT и TTS требуют отдельных адресов сервиса.

Память использует локальный FastEmbed `sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2`, выбранный из-за временной недоступности удалённого endpoint эмбеддингов. Модель уже скачана и проверена, размер вектора — 384. Кеш находится в `data/embedding-model`. При ошибке эмбеддингов поиск временно использует совпадения слов и пишет предупреждение в журнал.

Для запуска можно использовать `./run_alya.sh login`, затем `./run_alya.sh run` из корня проекта.

## Фоновая служба

На этой машине включена пользовательская служба `alya-next.service`. Она подключена к новому аккаунту Алы и запускается вместе с пользовательским systemd.

```bash
systemctl --user status alya-next.service
journalctl --user -u alya-next.service -f
systemctl --user restart alya-next.service
systemctl --user stop alya-next.service
```

После изменения `.env` или `config.toml` перезапустить службу. Одновременный ручной запуск защищён файловой блокировкой.

Для понимания фото настроена и проверена `Qwen-3.8-Max` через `VISION_MODEL`. Описание передаётся основному DeepSeek вместе с контекстом чата.
